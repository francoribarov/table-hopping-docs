# Agent Review — TableHopping Backend PR Review

Runs a comprehensive multi-agent review of the current branch against `develop`.
Launches specialist subagents in parallel, then synthesizes findings into a
prioritized action list.

---

## Step 1: Gather Git Context

Run these commands to collect the diff:

```bash
git fetch origin develop
git log --oneline origin/develop..HEAD
git diff --stat origin/develop...HEAD
git diff origin/develop...HEAD
```

Save the outputs:
- **Commit log** — summary of what changed and why
- **Diff stat** — file list with change size
- **Full diff** — line-by-line changes

---

## Step 2: Pre-Review Configuration

### Classify Conditional Reviewers

Inspect changed file paths from diff stat:

| Reviewer | Trigger paths |
|----------|---------------|
| **perf-reviewer** | `app/domain/services/`, `app/infrastructure/persistence/repositories/`, `app/api/endpoints/` |
| **data-layer-reviewer** | `app/infrastructure/persistence/`, `alembic/` |
| **api-design-reviewer** | `app/api/endpoints/`, `app/api/schemas/`, `app/api/router.py` |

### Ask the User

Before proceeding, ask:

1. "Should I run all conditional reviewers, or only those triggered by the changed files?"
2. "Any specific area to focus on? (architecture / data layer / API design / performance / all)"
3. "Any files to exclude from review? (e.g., autogenerated migration snapshots)"

---

## Step 3: Apply Scope Filter (if requested)

If the user selected a specific focus area, filter the diff to that scope before
passing to agents. Exclude generated/irrelevant files from all agent contexts:
- `__pycache__/`
- `*.pyc`
- `.pytest_cache/`
- `.mypy_cache/`

---

## Step 4: Build Staged Context Bundle

For **high-risk files** (new repositories, changed service contracts, auth/security
changes, core exception/DI changes), preload full file contents. This gives agents
complete context beyond the diff.

High-risk indicators:
- New classes implementing repository/service interfaces
- Changes to `app/api/service_dependencies.py` or `app/api/repository_dependencies.py`
- Changes to `app/core/exceptions.py` or `app/api/exception_mappers.py`
- Changes to auth/security dependencies, token handling, or password flows

For large diffs (>500 lines), preload at most 5-8 key files.

---

## Step 5: Identify Consumer Impact

For any **changed public interfaces** (repository interfaces, service interfaces,
schema contracts), find call sites and consumers:

```bash
rg "RentalServiceInterface|UserRepositoryInterface|SomeChangedSymbol" app/ tests/
```

Note which files consume the changed APIs. Pass this impact list to the
architecture-reviewer.

---

## Step 6: Launch Subagents in Parallel

**Always run (4 core agents):**
- `code-quality-reviewer` — correctness, quality, typing/linting compliance
- `bug-reviewer` — runtime errors, async defects, contract mismatches
- `architecture-reviewer` — layer boundaries, DI, service/repository structure
- `pre-pr-validator` — binary pass/fail mechanical compliance

**Conditional agents (based on Step 2 classification):**
- `perf-reviewer` — query patterns, async throughput, N+1 risks
- `data-layer-reviewer` — SQLAlchemy models/repositories/mappers/migrations
- `api-design-reviewer` — API contracts, status codes, schema consistency

**Each agent receives:**
1. Full git diff (filtered to scope)
2. List of changed files
3. Preloaded full file contents for high-risk files
4. Consumer impact map (for architecture-reviewer)
5. User's focus area (if specified)

Launch all selected agents in parallel and collect outputs.

---

## Step 7: Challenge Critical Findings

After all parallel agents complete, run `finding-challenger`:

**Pass it:**
- All Critical/Blocker findings from all agents (not Suggestions)
- Full file contents for each cited file
- Full diff

The challenger verifies each finding, renders CONFIRMED / DOWNGRADED / REJECTED
verdicts, and returns a verdict table.

---

## Step 8: Synthesize Final Report

Run `review-synthesizer` with:
- All parallel agent outputs
- Finding-challenger verdicts
- PR metadata (branch name, commits, diff stat)

The synthesizer applies challenger verdicts, deduplicates findings, and produces
the executive summary.

---

## Agent Context Template

When invoking each agent, provide:

```text
## Context

**Branch:** [current branch]
**Base:** origin/develop
**Commits:** [git log output]
**Files changed:** [diff stat]
**Focus area:** [user selection or "all"]

## Diff
[filtered git diff]

## Preloaded File Contents
[full contents of high-risk files]

## Consumer Impact Map
[list of files consuming changed APIs]
```

---

## Validation Commands (run locally before or after review)

```bash
make lint
make format-check
make typecheck
make test
make ci
```

---

## Review Pipeline Summary

```text
[git diff] -> [classify reviewers] -> [ask user] -> [build context]
    ↓
[parallel: code-quality + bug + architecture + pre-pr-validator]
    + [optional: perf + data-layer + api-design]
    ↓
[finding-challenger] -> validate all Critical findings
    ↓
[review-synthesizer] -> executive summary + action list
```
